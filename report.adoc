= Schema Alignment Report
:toc: left
:toclevels:3

== Summary

Aligns `prisma/schema.prisma`, backend API routes, validation schemas (`zod`), server actions, and frontend mock code to use consistent naming conventions (camelCase) and field definitions.

Branch: `chore/schema-alignment` (created from `docs/plan-v2-update`)

== Changes Made

=== 2. Schema Additions & Removals

==== 2.1 Added: `Recipe.visibility` field

Frontend create-recipe page uses 3 visibility states: `public`, `protected`, `private`.
The schema did not have this field.

**Command:** Added `visibility String @default("public")` to Recipe model.

==== 2.2 Added: `RecipeEquipment` model

Frontend create-recipe page allows adding equipment items (e.g., "หม้อทอดไร้น้ำมัน", "เครื่องปั่น").
No model existed for this.

**Command:** Added `RecipeEquipment` model with fields: `id`, `recipeId`, `name`, `createdAt`.
Table mapping: `recipe_equipment`.

==== 2.3 Removed: `Ingredient.role` and `Ingredient.discount`

These fields existed in the schema but were never referenced anywhere in the codebase (no API, no form, no validation, no mock data). Likely leftover from an older design.

=== 3. Naming Convention Audit

|===
| Layer | Convention | Status
| Prisma models | camelCase (`recipeName`, `isAnonymous`, `createdAt`) ✅ | Fixed
| Table names (`@@map`) | snake_case (`recipes`, `recipe_ingredients`) ✅ | Already consistent
| Zod validation keys | camelCase (was snake_case ❌ → now camelCase ✅) | Fixed
| API request JSON keys | camelCase (was snake_case ❌ → now camelCase ✅) | Fixed
| Frontend mock data | camelCase (already consistent) ✅ | No change needed
| Server action form data | reads from `formData.get("title")`, `formData.get("description")` — flat keys, no nesting issue ✅ | No change needed
|===

=== 4. Future / Not Yet Connected

The following frontend features have **no corresponding schema model** yet (documented here for future work):

- `SubCategory` model exists but search page uses hardcoded `categoriesData` array — no API integration
- `Category` model exists but no API endpoint returns categories
- `Shop` / store-front related fields (`shopName`, `sellingPrice`, `shopDescription`, `shopLocation`, `shopIngredientImages`) are frontend-only — no backend model exists
- `RecipeIngredient` has `quantity Float` and `unit String`, but create-recipe page tracks `category` per ingredient (meat, seafood, vegetable, fruit, seasoning) — this is purely UI state, not persisted
- `Recipe.status` / `bgColor` — only partially in schema (`bgColor` exists, `visibility` now added); no `status` (draft/published) field exists
