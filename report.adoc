= Registration Implementation Report
:toc: left
:toclevels: 3

== Summary

Implements end-to-end user registration with validation, duplicate checking, role assignment, and comprehensive test coverage. All changes follow existing project conventions (camelCase, Zod validation, Next.js server actions, Prisma ORM).

Branch: `feature/register-user` (created from `docs/plan-v2-update`)

== Changes Made

=== 1. Enhanced Validation Schema (`src/lib/validations/auth.schema.ts`)

**Password strength rules** (matching frontend client-side validation):
- Minimum 8 characters
- At least 1 uppercase letter
- At least 1 lowercase letter
- At least 1 number
- At least 1 special character

**New field: `role`**
- Type: `z.enum(['user', 'shop'])`
- Default: `'user'`
- Maps to Prisma: `'user'` → `'USER'`, `'shop'` → `'SHOP'`

=== 2. Rebuilt Server Action (`src/app/(auth)/register/actions.ts`)

Previously used raw Supabase admin client to insert into `users` table.
Now uses **Prisma** for:

1. **Duplicate email check** — `prisma.user.findUnique({ where: { email } })` before Supabase signup
2. **Duplicate username check** — `prisma.user.findUnique({ where: { username } })` before Supabase signup
3. **User creation** — `prisma.user.create()` with proper `id`, `email`, `username`, `role` mapping
4. **Error handling** — Specific Thai error messages for each failure case

=== 3. Frontend (`src/app/(auth)/register/page.tsx`)

No UI changes required — the form already had:
- Client-side password strength validation (8+ chars, uppercase, lowercase, number, special)
- Confirm password matching
- Role dropdown (คนทั่วไป/ร้านค้า)
- Server error display

The server action now properly reads `role` from `formData` and passes it to the validation schema.

=== 4. Test Files

==== 4.1 Unit Tests (`tests/register.test.ts`)

|===
| Category | Tests | Description
| Schema validation | 12 | Email, password strength, username length, role defaults/enum
| Duplicate detection | 3 | Pure logic: email taken, username taken, both available
| Role mapping | 3 | `user`→`USER`, `shop`→`SHOP`, fallback→`USER`
|===

**Edge cases covered:**
- Empty email, invalid email format
- Password missing each requirement (uppercase, lowercase, number, special)
- Password under 8 characters
- Username too short (< 2) or too long (> 30)
- Invalid role value (`'admin'`)
- Role defaults to `'user'` when omitted

**4.2 Integration Tests (`tests/register.api.test.ts`)**

|===
| Category | Tests | Description
| Validation rejection | 2 | Rejects invalid email/password at Zod level
| Duplicate rejection | 2 | Rejects duplicate email and duplicate username
| Success flow | 2 | Valid registration with USER and SHOP roles
| Error handling | 2 | Supabase failure, Prisma create failure
|===

All dependencies (Prisma, Supabase, Next.js navigation/cache) are mocked.
