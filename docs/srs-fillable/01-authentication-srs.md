### 1. บทนำ

#### 1.1 วัตถุประสงค์
ระบุวัตถุประสงค์ของเอกสารฉบับนี้เพื่ออธิบายข้อกำหนดของระบบการพิสูจน์ตัวตนในแอปพลิเคชัน Kinyrak Ingredients ว่าระบบนี้มีหน้าที่จัดการการสมัครสมาชิก การเข้าสู่ระบบ การออกจากระบบ การรีเซ็ตรหัสผ่าน และการจัดการบัญชีผู้ใช้งาน

#### 1.2 ขอบเขต
ระบบการพิสูจน์ตัวตนครอบคลุมฟังก์ชันต่อไปนี้:
- [ ] การสมัครสมาชิก (Register) ด้วยอีเมลและรหัสผ่าน
- [ ] การเข้าสู่ระบบ (Login) ด้วยอีเมลและรหัสผ่าน
- [ ] การออกจากระบบ (Logout)
- [ ] การรีเซ็ตรหัสผ่านทางอีเมล (Forgot Password)
- [ ] การเปลี่ยนรหัสผ่าน (Reset Password)
- [ ] การยืนยันอีเมล (Check Email)
- [ ] การลบบัญชีผู้ใช้งาน (Delete Account)
- [ ] การจัดการโปรไฟล์ (Username, Avatar)
- [ ] การใช้โทเค็น JWT ในการพิสูจน์ตัวตน
- [ ] การจำกัดสิทธิ์การเข้าถึงตามบทบาท (Role-Based Access Control)

#### 1.3 คำจำกัดความ
| ศัพท์ | ความหมาย |
|------|---------|
| **Authentication** | กระบวนการพิสูจน์ว่าผู้ใช้เป็นบุคคลที่อ้างสิทธิ์ |
| **JWT** | JSON Web Token - โทเค็นสำหรับพิสูจน์ตัวตน |
| **Role** | บทบาทของผู้ใช้ เช่น USER, STORE, ADMIN |
| **Supabase** | ผู้ให้บริการระบบจัดการฐานข้อมูลและยืนยันตัวตน |

### 7. ข้อจำกัด
- ต้องใช้ Supabase เป็นผู้ให้บริการยืนยันตัวตน
- อีเมลต้องได้รับการยืนยันก่อนใช้งานฟีเจอร์เต็มรูปแบบ
- ผู้ใช้ต้องลงทะเบียนก่อนจึงจะสามารถใช้งานระบบได้

### 8. สมมติฐาน
- Supabase Auth มีระบบแฮชรหัสผ่านที่ปลอดภัยแล้ว
- ผู้ใช้มีอีเมลที่ใช้งานได้จริง
- ระบบสามารถเชื่อมต่อกับ Supabase ได้ตลอดเวลา
