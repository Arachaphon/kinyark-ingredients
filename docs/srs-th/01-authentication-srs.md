## บทที่ 1 บทนำ

### 1.1 วัตถุประสงค์

เอกสารฉบับนี้มีวัตถุประสงค์เพื่อบันทึกข้อกำหนดของระบบการพิสูจน์ตัวตนในแอปพลิเคชัน "กินยากร-ingredients" ซึ่งทำหน้าที่จัดการการสมัครสมาชิก การเข้าสู่ระบบ การออกจากระบบ การรีเซ็ตรหัสผ่าน และการจัดการบัญชีผู้ใช้งาน เพื่อให้มั่นใจว่าผู้ใช้สามารถเข้าถึงระบบได้อย่างปลอดภัยและถูกต้องตามสิทธิ์ที่ได้รับ

### 1.2 ขอบเขต

ระบบการพิสูจน์ตัวตนครอบคลุมฟังก์ชันดังต่อไปนี้:

1. การสมัครสมาชิก (Register) ด้วยอีเมลและรหัสผ่าน
2. การเข้าสู่ระบบ (Login) ด้วยอีเมลและรหัสผ่าน
3. การออกจากระบบ (Logout)
4. การรีเซ็ตรหัสผ่านทางอีเมล (Forgot Password)
5. การเปลี่ยนรหัสผ่าน (Reset Password)
6. การยืนยันอีเมล (Check Email)
7. การลบบัญชีผู้ใช้งาน (Delete Account)
8. การจัดการโปรไฟล์ (Username, Avatar)
9. การใช้โทเค็น JWT ในการพิสูจน์ตัวตน
10. การจำกัดสิทธิ์การเข้าถึงตามบทบาท (Role-Based Access Control)

### 1.3 คำจำกัดความ

| ศัพท์ | ความหมาย |
|------|---------|
| **การพิสูจน์ตัวตน (Authentication)** | กระบวนการตรวจสอบว่าผู้ใช้เป็นบุคคลที่อ้างสิทธิ์จริง |
| **โทเค็น (Token)** | ข้อมูลดิจิทัลที่ใช้ในการพิสูจน์ตัวตนของผู้ใช้ในแต่ละเซสชัน |
| **บทบาท (Role)** | ประเภทของผู้ใช้ที่กำหนดสิทธิ์การเข้าถึง เช่น USER, STORE, ADMIN |
| **ผู้ให้บริการยืนยันตัวตน** | บริการภายนอกที่จัดการการพิสูจน์ตัวตน เช่น Supabase Auth |

### 1.4 การอ้างอิง

- เอกสารข้อกำหนดสถาปัตยกรรมระบบ Kinyrak Ingredients
- คู่มือการใช้งาน Supabase Auth SDK
- คู่มือการใช้งาน Next.js App Router

## บทที่ 7 ข้อจำกัด

- ระบบต้องใช้ผู้ให้บริการยืนยันตัวตนจากภายนอก (เช่น Supabase)
- อีเมลต้องได้รับการยืนยันก่อนใช้งานฟีเจอร์เต็มรูปแบบ
- ผู้ใช้ต้องลงทะเบียนก่อนจึงจะสามารถใช้งานระบบได้
- รหัสผ่านต้องมีความยาวอย่างน้อย ____ ตัวอักษร
- ระบบไม่รองรับการเข้าสู่ระบบแบบใช้ชื่อผู้ใช้อย่างเดียว

## บทที่ 8 สมมติฐาน

- ผู้ใช้มีอีเมลที่ใช้งานได้จริงและสามารถเข้าถึงได้
- ระบบสามารถเชื่อมต่อกับผู้ให้บริการยืนยันตัวตนได้ตลอดเวลา
- ผู้ใช้มีความรู้พื้นฐานในการใช้งานอินเทอร์เน็ต
- ผู้ให้บริการยืนยันตัวตนมีระบบความปลอดภัยที่เพียงพอ

### 9.1 กรณีทดสอบ

| รหัส | รายละเอียด | ขั้นตอน | ผลลัพธ์ที่คาดหวัง |
