==== Vulnerability Detail

[WARNING]
====
*Finding #1 — Unstable Identifier Lookup*

`src/app/api/auth/me/route.ts:14`:
[source,typescript]
----
const dbUser = await prisma.user.findUnique({
  where: { email: user.email! }, // BUG: lookup by email
  select: { id: true, username: true, email: true, avatarUrl: true }
});
----

- `email` is mutable (user can change it). `id` is immutable.
- `user.email!` throws if email is null (possible in some Supabase configurations).

*Impact*: Profile lookup fails silently → frontend receives `{ user: { email } }` instead of full profile.
*Severity*: MEDIUM
====

[WARNING]
====
*Finding #2 — Inconsistent Response Shape*

`src/app/api/auth/me/route.ts:19`:
[source,typescript]
----
return NextResponse.json({ user: dbUser || { email: user.email } });
----

Two different shapes returned depending on whether `dbUser` exists:

1. `{ user: { id, username, email, avatarUrl } }` — when Prisma record exists
2. `{ user: { email } }` — fallback when Prisma record missing

*Impact*: Frontend must branch on response shape or risk `undefined` property access.
*Severity*: LOW

== Recommendations

. === Immediate Fix — `/api/auth/me` (Priority: HIGH)

Replace email-based lookup with id-based lookup and consistent return:

[source,typescript]
----
export async function GET() {
  try {
    const supabase = await createClient()
    const { data: { user } } = await supabase.auth.getUser()

    if (!user) {
      return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })
    }

    const dbUser = await prisma.user.findUnique({
      where: { id: user.id },
      select: { id: true, username: true, email: true, avatarUrl: true }
    })

    if (!dbUser) {
      return NextResponse.json({ error: 'Not found' }, { status: 404 })
    }

    return NextResponse.json({ user: dbUser })
  } catch {
    return NextResponse.json({ error: 'Internal Server Error' }, { status: 500 })
  }
}
----

Key changes:

- `where: { id: user.id }` — stable identifier
- Removed `user.email!` — no null crash risk
- Return 404 when `dbUser` is null — consistent shape always `{ user: {...} }`

. === Cleanup — `/api/users/me` (Priority: LOW)

Remove excessive blank lines for readability. No logic changes needed.
