# รายงานผลการทดสอบระบบ (Manual Test Results) - W1-5 Update Recipe (PATCH)

## 🟢 Positive Test Cases

### 1. เจ้าของสูตรอาหาร (Recipe Owner) อัปเดตข้อมูลสูตรอาหารของตนเองสำเร็จ
**วิธีทดสอบ (Steps):**
1. ล็อกอินเข้าสู่ระบบด้วยบัญชีที่เป็นผู้สร้างสูตรอาหารนั้นๆ
2. ไปที่หน้า "สูตรอาหารของฉัน" (My Recipe)
3. เลือกสูตรอาหารที่ต้องการแก้ไข แล้วกดปุ่มแก้ไขสูตรอาหาร
4. ปรับเปลี่ยนข้อมูลบางส่วน เช่น:
   - เปลี่ยนชื่อสูตรอาหาร
   - เพิ่มหรือลบส่วนผสม/อุปกรณ์
   - ปรับเปลี่ยนรูปภาพหรือวิดีโอ
5. กดบันทึกการแก้ไขข้อมูลสูตรอาหาร

**ผลที่คาดหวัง (Expected Results):**
- [/] ระบบสามารถส่งคำขอแก้ไขผ่าน Method `PATCH` ไปยัง `/api/recipes/[id]` สำเร็จ ได้รับ HTTP Status `200 OK`
- [/] ข้อมูลสูตรอาหารในระบบเปลี่ยนไปตามที่แก้ไขจริง
- [/] เมื่อกลับมาดูรายละเอียดสูตรอาหาร ข้อมูลที่แก้ไขแสดงผลได้อย่างถูกต้องสมบูรณ์

---

### 2. เจ้าของสูตรอาหารปรับเปลี่ยนสิทธิ์การมองเห็น (Visibility) สำเร็จ
**วิธีทดสอบ (Steps):**
1. ล็อกอินด้วยบัญชีเจ้าของสูตรอาหาร
2. เลือกแก้ไขสูตรอาหารและทดลองเปลี่ยนสิทธิ์การมองเห็นเป็นค่าต่างๆ ได้แก่:
   - `"public"` (สาธารณะ)
   - `"protected"` (สาธารณะจำกัดสิทธิ์ - STORE มองไม่เห็น ยกเว้นเจ้าของสูตร)
   - `"private"` (ส่วนตัว)
3. กดบันทึกข้อมูลสูตรอาหารในแต่ละครั้ง

**ผลที่คาดหวัง (Expected Results):**
- [/] สามารถปรับเปลี่ยนระดับสิทธิ์และอัปเดตไปยังฐานข้อมูลได้เรียบร้อย ได้รับ HTTP Status `200 OK`
- [/] ระบบจำกัดการแสดงผลตามสิทธิ์ใหม่ที่บันทึกได้อย่างถูกต้อง เช่น เมื่อเปลี่ยนเป็น `private` ผู้ใช้อื่นจะไม่สามารถเปิดดูได้ แต่เจ้าของสูตรยังคงเข้าดูได้

---

### 3. เจ้าของโพสต์ร้านค้า (Store Post Owner) อัปเดตข้อมูลการขายของตนเองสำเร็จ
**วิธีทดสอบ (Steps):**
1. ล็อกอินด้วยบัญชีร้านค้าที่เป็นคนโพสต์ขายสูตรนั้น (แต่ไม่ได้เป็นเจ้าของสูตรต้นฉบับ)
2. เข้าไปที่เมนูแก้ไขของโพสต์ดังกล่าว
3. ปรับเปลี่ยนเฉพาะข้อมูลการขาย เช่น:
   - เปลี่ยนราคาขาย (sellingPrice)
   - แก้ไขรายละเอียดโพสต์ร้านค้า (storeDescription)
4. กดบันทึกการแก้ไข

**ผลที่คาดหวัง (Expected Results):**
- [/] ระบบทำการส่งคำขอและอัปเดตข้อมูลส่วนร้านค้าลงตาราง `StorePost` สำเร็จ ได้รับ HTTP Status `200 OK`
- [/] ข้อมูลร้านค้าและราคาที่แสดงบนหน้ารายละเอียดได้รับการอัปเดตตามที่แก้ไข

---

## 🔴 Negative Test Cases

### 4. ผู้ใช้ที่ไม่ใช่เจ้าของพยายามแก้ไขข้อมูลสูตรอาหารหลัก (Forbidden)
**วิธีทดสอบ (Steps):**
1. ล็อกอินด้วยบัญชีร้านค้าที่เข้ามาสร้างโพสต์ขายจากสูตรคนอื่น
2. พยายามเรียกใช้ API หรือส่ง Form แก้ไขเพื่อปรับปรุงข้อมูลสูตรอาหารหลัก (เช่น `recipeName` หรือ `description` ของสูตร)
3. กดส่งบันทึก

**ผลที่คาดหวัง (Expected Results):**
- [/] ระบบปฏิเสธคำขอและส่งคืน HTTP Status `403 Forbidden`
- [/] ได้รับ Error แจ้งเตือน: `"Forbidden: you can only edit your store post fields"`
- [/] ข้อมูลของสูตรอาหารหลักในระบบไม่ได้รับการเปลี่ยนแปลงใดๆ

---

### 5. บุคคลภายนอกที่ไม่ได้รับสิทธิ์พยายามแก้ไขข้อมูล (Forbidden / Unauthorized)
**วิธีทดสอบ (Steps):**
1. **ทดสอบแก้สูตรของคนอื่น:** ล็อกอินด้วยบัญชี User A แล้วลองส่งคำขอ `PATCH` ผ่านโปรแกรมทดสอบ API (เช่น Postman/Curl) ไปที่ ID ของสูตรที่เป็นของ User B
2. **ทดสอบแก้แบบไม่ล็อกอิน:** ส่งคำขอ `PATCH` โดยไม่มี Authentication Header ใดๆ

**ผลที่คาดหวัง (Expected Results):**
- [/] กรณีไม่ใช่เจ้าของ: ระบบปฏิเสธการแก้ไข ส่งคืน HTTP Status `403 Forbidden`
- [/] กรณีไม่ล็อกอิน: ระบบปฏิเสธและส่งคืน HTTP Status `401 Unauthorized`

---

### 6. อัปเดตด้วยข้อมูลที่ไม่ถูกต้องตามข้อกำหนด (Validation Failures)
**วิธีทดสอบ (Steps):**
1. ล็อกอินด้วยบัญชีเจ้าของสูตรอาหาร
2. ลองแก้ไขโดยป้อนข้อมูลที่ผิดรูปแบบ เช่น:
   - ปล่อยชื่อสูตรว่างเปล่า (`recipeName: ""`)
   - ส่งรูปแบบข้อมูลอื่นๆ ไม่ตรงตาม Schema
3. กดส่งการแก้ไข

**ผลที่คาดหวัง (Expected Results):**
- [/] ระบบปฏิเสธคำขอและส่งคืน HTTP Status `400 Bad Request` พร้อมแจ้งข้อผิดพลาดของข้อมูล (Validation Error)
- [/] ฐานข้อมูลยังไม่มีการอัปเดตจนกว่าผู้ใช้จะแก้ไขข้อมูลให้ถูกต้อง
